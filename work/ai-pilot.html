01

Project Overview

The Product
Skara AI Agent Builder - part of Salesmate's AI Agents platform. A no-code tool for building and deploying AI agents across web, WhatsApp, SMS, and voice channels.
The Goal
Make AI agent setup accessible to non-technical sales managers - removing the dependency on developers for every new agent configuration.
My Contribution
End-to-end product design - user research, information architecture, high-fidelity UI, design system components, and developer handoff.
Design System
New components built on Salesmate's Global Design System and fed into sm-framework - Salesmate's internal Angular component library.

Salesmate customers wanted to use AI to automate support and sales conversations - but existing tools required coding knowledge or complex API setup. The goal was to abstract that complexity into a flow that felt like onboarding a new team member, not programming a system.

02
"How might we help non-technical sales managers build, train, and deploy safe AI agents without writing a single line of code?"
01 - COMPLEXITY
AI is intimidating
Terms like "temperature," "tokens," and "system prompts" mean nothing to a sales manager. The interface needed to hide the technical layer entirely.
02 - TRUST
Fear of hallucination
Users were worried the AI would give wrong answers to their customers. They needed full visibility into what the agent "knows" before it goes live.
03 - CONFIDENCE
No way to test
Without a way to preview the agent's behaviour in real time, users had no confidence to deploy. Testing had to be built into the setup flow itself.

The AI Pilot Builder is designed around five interconnected layers. Each layer adds context, intelligence, behavior, or execution capabilities until the agent becomes ready for production use.

Identity defines who the agent is. Knowledge teaches what it knows. Behavior controls how it responds. Tools determine what it can do. Deployment decides where it operates.

Together these five layers transform a simple prompt into a production-ready AI agent.

05

Key Design Decisions

A
The Hiring Mental Model
Talk Like a Manager, Not a Developer
Instead of asking for a "system prompt," I designed fields for Role, Goal, and Tone - language the user already understands. The system translates these inputs into the technical configuration in the background. The user never sees that layer.
Identity / Setup Tab

What the user sees — and what they don't

The Setup tab surfaces four fields: name, language, a plain-text identity instructions area, and a tone picker with five options — Formal, Casual, Humorous, Friendly, Matter-of-fact. That's it. No model selection. No temperature. No token limits.

The constraint was deliberate — a sales manager shouldn't have to understand what temperature means to build a working agent. The tone picker replaced the concept of a system prompt entirely. Users pick a personality. The platform handles the rest.

Hidden Layer

The layer that doesn't exist for the user

Behind the four-field Setup UI sits a full technical configuration layer — LLM model selection, temperature control, priority processing toggles, and context window management. Every decision made at that layer is invisible to the end user.

The design question wasn't how to present these settings — it was whether to present them at all. The answer was no. We made the decision once at the system level and removed the choice from the user entirely. That's not simplification — that's a deliberate product decision that required alignment across design, engineering, and the CEO.

B
The Knowledge Base
Show the Agent Exactly What It Knows
To solve the trust problem, I designed a transparent file manager. Users can see every PDF, URL, and document the agent is reading from. If something is outdated or wrong, they can remove it instantly - giving them full control before going live.
Knowledge Base Setup

Giving the agent a brain — without a single line of code

The Knowledge Base setup runs as a two-step flow: basic details first, then category selection. The category step uses a grid of pre-defined options — Getting Started, FAQs, Troubleshooting, Integrations, and others — so users don't start from a blank slate.

This was one of the more important UX decisions in the product: an empty state is the fastest way to lose a non-technical user. By showing categories rather than a blank text field, we gave users a framework to think within — and most filled it faster than any blank form would have allowed.

Article Editor with AI Controls

Transparency at the article level

Each article in the Knowledge Base carries two explicit controls: one for whether the AI Pilot can use it to answer customer questions, and one for whether AI Copilot can reference it to assist human agents. These aren't global settings — they live on every individual article.

That granularity was a direct response to the trust problem. Users needed to feel that they controlled what the agent knew, article by article, before they'd be willing to deploy it to real customers. The toggles are the product's trust mechanism — more than any other design decision in the flow.

C
The Real-Time Playground
Test Before You Deploy
A split-screen view: settings on the left, live chat preview on the right. Change the tone, the agent responds differently - immediately. This tight feedback loop let users experiment freely and build confidence before going live. No deployment anxiety.
Prompt Training & Testing

The feedback loop that built confidence

The Playground is a prompt training and testing interface. Users define System and User prompts, click Run, and see the AI Pilot's response immediately. The key design decision here was speed of feedback — the response had to appear fast enough that users felt they were having a conversation with the agent, not submitting a form and waiting.

That tight write → run → adjust loop is what turned a feature that initially felt intimidating into something users returned to repeatedly before deploying. We saw this in beta testing: users who spent time in the Playground deployed more confidently and requested fewer changes post-launch.

07
"The success wasn't just in the UI - it was in the abstraction. We hid the complexity of AI behind a flow that felt like hiring a new team member."
Self-Serve Setup
Agent configuration moved from a developer-dependent process to something any sales manager can complete independently - no technical knowledge required.
User Confidence
The transparent knowledge base and real-time playground removed the fear of deployment. Users could see exactly what the agent knew and test it before going live.
Scalable Architecture
The five-layer architecture - Identity, Knowledge, Behavior, Tools, Deployment - scaled across eCommerce, retail, enterprise, and agency use cases without needing a redesign.
