01

Overview

Document Templates lets Salesmate users create, manage, and reuse branded document layouts for the Quotes module only. This feature is scoped exclusively to quotes - it does not apply to other CRM modules. Instead of building a quote document from scratch each time, teams create a template once - with cover page, content layout, header/footer, and watermark - and apply it whenever they generate a quote.

Three default system templates ship with every account (Basic, Modern, Original) - read-only, but cloneable as a starting point. Users with "Manage Document Template" permission can create, edit, clone, and delete custom templates. A template cannot be deleted while actively in use by open quotes - only once those quotes reach completed status or are hard-deleted.

02

Design Decisions

A
Template Management
Card Grid Library with Safe Delete Rules
The library needed to let teams manage templates while preventing actions that could break active quote documents.
The library isn't storing documents - it's protecting business operations

Document Templates appears to be a simple template library, but the real challenge was governance. Templates aren't isolated assets. They're dependencies used by active quotes that may already be part of a sales process.

The product needed to balance two competing requirements: allowing teams to manage and clean up templates while preventing actions that could break active business documents. That's why the system ships with three protected default templates and restricts deletion when a template is still referenced by open quotes.

What looks like a template gallery is actually a management layer enforcing document integrity across the Quotes module. Users are free to customize, clone, and evolve their templates, but the system prevents changes that would create inconsistencies in active customer-facing documents.

The goal wasn't template management. The goal was operational safety.

B
Progressive Creation Flow
A Single Toggle Adds an Entire Step
The creation flow supports simple quote templates by default, then expands only when a user chooses to add branded document structure.
A single toggle changes the workflow, not the complexity

The creation flow supports both simple and highly branded quote documents. The challenge was exposing advanced capabilities without forcing every user through additional configuration.

The solution was progressive architecture rather than progressive disclosure alone. Enabling a cover page doesn't reveal a few extra settings - it inserts an entirely new step into the workflow. The system adapts its structure based on the user's intent.

This decision matters because most users create straightforward quote documents. Forcing everyone through cover page configuration would increase complexity for the majority. At the same time, teams investing heavily in branding need significantly more control.

The creation flow expands only when the user's requirements expand. Complexity enters the system by choice rather than by default.

C
Cover Page Builder
A Focused Canvas - Limited Elements by Design
The cover page builder uses familiar editing patterns, but deliberately limits what a cover page can become.
Deliberate constraints create better documents

The Cover Page Builder uses the same editing foundation as the main document builder, but with a deliberately restricted set of capabilities.

The design challenge wasn't deciding what to add. It was deciding what not to add.

Without constraints, cover pages quickly become second documents, filled with unnecessary content, repeated information, and inconsistent layouts. The builder therefore supports only the elements required to create a strong first impression while intentionally excluding capabilities that belong inside the document itself.

The one-cover-page limit follows the same philosophy. A cover page has a specific purpose: introduce the document and establish branding. Once it starts behaving like a content section, it stops serving that purpose.

The constraints aren't limitations. They're guardrails that preserve the role of the cover page within the larger document experience.

D
Design Settings - Watermark
Branding, Copyright, or Security Watermarks - Per Page Control
Watermarks needed to support branding, compliance, ownership, and exceptions without making every page a configuration burden.
Branding and document control needed different levels of authority

Watermarks seem like a visual customization feature, but they introduce a governance problem. Some organizations use them for branding. Others use them for compliance, ownership identification, or internal document control.

The challenge was creating a system that worked at both the template level and the page level without becoming difficult to manage.

The solution was a layered model. Watermarks are configured globally so templates maintain consistency by default. Individual pages can then override that decision when specific content requires different treatment.

This prevents teams from repeatedly configuring watermark settings across every page while still giving them the flexibility to make exceptions when needed.

What appears to be a branding feature is actually a document governance system with visual output.

Text Watermark
Options
  • Text content (max 50 characters)
  • Direction - 9 diagonal, horizontal, and vertical options
  • Font Family - selectable typeface
  • Text Color - default #5148E5
  • Scale - 1 to 100%, default 20%
Image Watermark
Options
  • Background image upload - PNG, JPG, JPEG, max 5MB
  • Image Opacity - 0 to 100%, default 14%
  • Direction - 4 options (diagonal + horizontal + vertical)
  • Scale - 1 to 100%, default 20%
  • Per-page override via Page Settings → Apply Watermark toggle
03

Feature Summary

3 Default Templates
Basic, Modern, and Original ship with every account. Read-only - users clone them to customise rather than editing originals.
Safe Delete Logic
A template in active use by open quotes cannot be deleted. Only templates used in completed or hard-deleted quotes are deletable - preventing broken documents.
Cover Page Toggle
A single toggle on the Basic Information step inserts the Cover Page step into the creation flow - progressive disclosure that doesn't add complexity for users who don't need it.
Cover Page Elements
Text, Text Section, Image, Video, Table, Divider - a scoped set focused on first-impression design. No header/footer. One cover page per template maximum.
Text & Image Watermarks
Applied globally across all pages from Design Settings. Each page can override via its own Page Settings panel - turn off the watermark for specific pages without affecting others.
Clone & Search
Any template can be cloned as a starting point for a new one. Templates are searchable by name - filter by module also available for future multi-module expansion.
04

Outcome

Reusable & Consistent
Teams create a quote template once and reuse it across all quotes. Three default templates mean teams can start sending branded quotes immediately - no setup required.
Brand-Ready Documents
Cover pages, watermarks (text or image), company logo, and background image controls give teams the tools to produce professional, on-brand quote documents directly from the CRM.
Safe by Default
Default templates can't be deleted. Active templates can't be deleted. Every design decision defaults to the safest state - users only unlock more if they deliberately opt in.
